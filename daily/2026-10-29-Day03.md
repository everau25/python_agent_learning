## 今天学了什么（老师笔记大纲）

1. Python 概念与安装：Python 是解释型语言，代码要靠解析器转成机器能懂的语言才能跑；常用解析器是 CPython（官方，C 语言写的）；生产环境不追最新版，老师建议 Python 3.8 及以上，常用 3.11 等。
2. PyCharm：Python 最常用的 IDE，社区版免费，基础班够用；功能包括项目管理、智能提示、语法高亮、代码跳转、调试、解释器配置。
3. Anaconda 的使用：最大的好处是沙箱机制，环境隔离（见下面重点 1）。
4. 注释与快捷键：单行 `#`，多行 `""" """` 或 `''' '''`；`Ctrl + /` 快速注释，`Ctrl + D` 复制一行，`Ctrl + Alt + L` 格式化，`Ctrl + S` 保存，`Ctrl + Z` 撤销。
5. 变量：变量是存数据的容器，运行中可变，存的是临时的；先定义后使用；命名只能用数字、字母、下划线，不能数字开头，严格区分大小写，不能用关键字；推荐见名知意，下划线命名如 `my_name` 最常用。
6. 数据类型：Python 一共 7 种，数值（int、float）、布尔（True、False）、字符串、列表、元组、集合、字典；今天只要求前 3 种。判断类型用 `type(变量)`，判断是不是某类型用 `isinstance(变量, 类型)`，返回 True / False。注意：变量本身没有固定类型，类型取决于等号右边的值，同一个变量名重新赋值会覆盖。
7. 输入与输出：`print()` 输出，`input('提示：')` 输入；input 拿到的永远是字符串，哪怕用户输入的是数字；格式化输出三种写法：`%s/%d/%f`、`'{}'.format(...)`、推荐的 f-string `f'姓名：{name}'`；转义符 `\n` 换行、`\t` 制表。
8. 数据类型转换：`int(x)` 转整数，`float(x)` 转小数，`str(x)` 转字符串；`'3.5'` 不能直接 `int()`，要先 `float()`，`int(3.5)` 会丢掉小数位只留 3；input 来的价格要先 `float(price)` 才能做 `price * 1.1` 这种运算。转换表里还有一个 `eval(str)`，就是下面重点 2。

## 重点 1：Anaconda 环境切换（今天的重点之一）

### 1.1 先分清三个词，别混了

- **Conda**：工具本身，管包、管环境的命令行工具。
- **Anaconda**：全家桶发行版，里面有 Conda + Python + 1500 多个数据科学库 + 图形工具，体积大。
- **Miniconda**：迷你版，只有 Conda + Python + 少量核心依赖，体积小，想装什么自己再装。

你电脑上装的是 Anaconda，PyCharm 右下角显示的解释器在 `D:\Program Files\anaconda`，那就是 Anaconda 的 base 环境。

### 1.2 为什么非要切换环境？一句话：沙箱隔离

一个环境就是一个独立的小房间，里面的 Python 版本和装的库互不干扰。

以后学机器学习、深度学习最能体会到：A 项目要用 Python 3.9 + 某个旧版 torch，B 项目要用 Python 3.10 + 新版库，装在同一个环境里就会互相打架、版本冲突。分开建环境，A 用 A 的，B 用 B 的，出了问题也只影响那一个环境，不会把 base 环境搞脏。

所以原则是：**base 环境保持干净，只做通用事；每个项目、每门课的阶段，单独建一个环境。**

### 1.3 切换环境的完整步骤（都在 Anaconda 终端里做）

老师笔记里说的终端，就是开始菜单里的 Anaconda Prompt / Anaconda Powershell Prompt，不是普通的 Python 交互窗口，也不是直接在代码文件里写这些命令。

**第 0 步：打开终端，确认装好了**

```bash
conda -V
python -V
```

能打出版本号，就是装好了。

**第 1 步：看现在有哪些环境**

```bash
conda env list
# 也可以写成 conda info --envs，效果一样
```

输出里前面带 `*` 的，就是当前正在用的环境。`base` 叫基础环境，老师笔记里说 base 自带的 Python 是 3.12.4。

**第 2 步：新建一个环境**

```bash
conda create -n 环境名 python=3.9
```

- `create` = 创建，`-n` = name（名字），`python=3.9` = 指定这个环境里的 Python 版本。
- 老师笔记里的例子：`conda create -n sz10_py310 python=3.10`，意思是建一个叫 `sz10_py310`、Python 3.10 的环境。**`sz10_py310` 是老师的例子名，不是你的环境名，你自己的环境名按你建的时候起的名字为准。**
- 执行后它会列出要下载的东西，问你 Proceed ([y]/n)，输入 `y` 回车，等下载完。

**第 3 步：激活环境（这才是真正的“切换”）**

```bash
conda activate 环境名
# 例子：conda activate sz10_py310
```

激活后，终端最前面的括号会变成 `(环境名)`，这就是切换成功的标志。这时再跑：

```bash
python -V
```

显示的就应该是这个环境里的 Python 版本，而不是 base 的版本了。在这个环境里 `pip install` / `conda install` 装的库，也只装进这个环境，不会装进 base。

**第 4 步：用完退出当前环境**

```bash
conda deactivate
```

跑一次就回到 base；如果还想彻底退出 Conda 的激活状态，再跑一次也行，日常用一次就够了。

**第 5 步：删除环境（删之前先退出它）**

```bash
conda remove -n 环境名 --all
# 或者：conda env remove -n 环境名
```

两句效果一样，`--all` 就是把这个环境整个删掉。删是不可逆的，删之前先 `conda deactivate` 退出它，别在正用着的环境里删自己，也别删 base。

**第 6 步：看当前环境里装了什么库**

```bash
conda list
```

这个命令只列当前激活环境里的库，换了环境再跑，列表就不一样了——这就是隔离最直观的证据。

### 1.4 在 PyCharm 里切换环境（和终端切换要对上）

终端里 `conda activate` 只管终端，PyCharm 里跑代码用的是 PyCharm 右下角那个解释器，两边要设成同一个环境，代码才不会出现“终端里能跑、PyCharm 里找不到包”或者反过来的情况。

老师笔记里的操作路径是：File → Settings → Project → Python Interpreter → 换解释器 / 添加解释器 → 选 Conda Environment → 选已经建好的环境，或者直接选那个环境里的 `python.exe`。

环境里的 `python.exe` 一般在下面这种位置（以你的 Anaconda 安装盘为准，环境名换成你自己的）：

```
D:\Program Files\anaconda\envs\环境名\python.exe
```

base 环境的则是：

```
D:\Program Files\anaconda\python.exe
```

设完之后，PyCharm 右下角显示的解释器路径、以及 PyCharm 里打开终端时前面括号里的环境名，应该和你在 Anaconda 终端里激活的是同一个。

### 1.5 环境存到哪个盘？（老师笔记里补充的两种方法）

默认新环境存在 Anaconda 安装目录下的 `envs` 里。如果想改到别的盘，推荐第一种：

**方法一：命令直接改（推荐）**

在 Anaconda Prompt 里跑，把 `D:\conda_envs` 换成你想要的路径：

```bash
conda config --add envs_dirs D:\conda_envs
```

`--add` 会把新路径加到列表最前面，变成新环境的默认位置。已经建好的旧环境不受影响，Conda 还是能找到它们。

**方法二：手动改 `.condarc` 文件**

用记事本打开 `C:\Users\你的用户名\.condarc`，加上：

```yaml
envs_dirs:
  - D:\conda_envs
```

保存后，新建环境就优先存到这个目录。两种方法选一种就行，不用两个都做。

### 1.6 最容易踩的几个坑

- **忘了 activate 就装包**：包会装进 base 或者装进上一个环境，跑代码时提示找不到包。装包之前先看终端前面的括号是不是你要的那个环境。
- **终端和 PyCharm 各用各的环境**：终端里激活了 A，PyCharm 解释器还是 base，代码跑起来用的库就不一样。两边对齐一次，后面就顺了。
- **在 base 里乱装项目库**：base 脏了，以后所有项目都受影响。项目库一律装进项目自己的环境。
- **删环境时还在里面**：先 `conda deactivate`，再 `conda remove`，别删 base。

## 重点 2：eval（今天的重点之二，老师说后面深度学习、机器学习要掌握）

### 2.1 eval 一句话是什么

`eval(str)`：把一个**字符串**当成 Python 代码（表达式）来执行，并把计算结果返回出来。

```python
eval('1+1')   # 2
```

注意两个词：输入必须是字符串，输出是计算出来的对象（数字、列表、字典等都可能）。

它在老师笔记的类型转换表里就是这一行：`eval(str) | 用来计算在字符串中的有效 Python 表达式，并返回一个对象`。

### 2.2 先把课上那份 `09.eval.py` 一行一行讲清楚

原文件（注意：原文件里用 `str` 当变量名，这个习惯不要学，原因见 2.4）：

```python
str = 1 + 1  # 计算
print(str)   # 2，数字相加

#str = 1+ "1"  # 报错：整型和字符串不可以相加
#print(str)

str = "1" + "1"  # 字符串拼接
print(str)       # 11，注意这是字符串 "11"，不是数字 11

str = eval( "1" + "1" ) # 没有变化  执行的效果 "1"+"1" = 11   eval(11) -> 输出11
print(str)       # 11，但这次是数字 11

# eval 可以将一个字符串变成可执行的代码片段
str = '1+1'
str = eval('1+1') # 整个结果就是 '1+1'  eval('1+1') -> 计算 1+1 的结果
print(str)       # 2，数字
```

**最容易搞混的，是倒数第二段和最后一段的区别：**

- `eval("1" + "1")`：Python 是先算括号里的 `"1" + "1"`，得到字符串 `"11"`，再把 `"11"` 交给 eval，eval 把 `"11"` 当成数字表达式算出来，得到数字 `11`。所以它不是算 `1+1`，是先拼接、后求值，结果是 11。
- `eval('1+1')`：直接把字符串 `'1+1'` 交给 eval，eval 看到里面有个 `+`，就按加法算，得到数字 `2`。

一句话区分：**`"1" + "1"` 是拼接，结果是 `"11"`；`eval('1+1')` 是计算，结果是 `2`。**

前面注释掉的那行 `1 + "1"` 会报错，是因为在 eval 还没出场之前，Python 就已经在算 `1 + "1"` 了，数字和字符串不能直接相加，类型对不上，程序在这里就停了，跟 eval 没关系。

### 2.3 扩展例子（不是老师原文件里的，是按老师这个知识点顺着展开的）

```python
eval('2 * 3 + 4')        # 10，先乘除后加减，eval 按 Python 运算规则算
eval('10 / 4')           # 2.5
eval('1.5')              # 1.5，字符串 "1.5" 变成小数
eval('[1, 2, 3]')        # [1, 2, 3]，字符串变成真的列表
eval("{'lr': 0.01, 'batch': 32}")  # {'lr': 0.01, 'batch': 32}，字符串变成真的字典
eval('True')             # True，字符串变成布尔值

x = 10
eval('x + 1')            # 11，eval 能用到当前已经定义好的变量 x
```

**和 input 连起来，是 eval 最常见的用法，也是它为什么在后面有用的地方：**

```python
# input 拿到的永远是字符串
s = input('请输入一个表达式：')  # 比如用户输入 1+1
print(eval(s))  # 2

s = input('请输入一个列表：')    # 比如用户输入 [64, 128]
print(eval(s))  # [64, 128]，真的列表，后面可以直接 len()、循环、取下标
```

没有 eval，`"[64, 128]"` 就只是一串字符，没法当列表用；有了 eval，字符串就变成了程序里能直接用的数据。

### 2.4 为什么老师说后面深度学习、机器学习要掌握它？

因为后面很多地方，参数一开始都不是现成的数据，而是以字符串形式来的：

- 训练时在终端 / 配置里输入的超参数：学习率 `"0.001"`、批量大小 `"32"`、网络层数 `"[64, 128, 256]"`，读进来是字符串，要变成数字、列表、字典才能喂给模型。
- 配置文件、命令行参数、交互式输入里写的一行表达式，想让它直接变成可计算、可用的值，而不是手动一个一个拆字符串。
- 做实验时快速验证一个公式、一个数据结构，不用改代码重跑，直接把字符串丢给 eval 就能看到结果。

理解到这一层就够了：**eval 是“字符串 → 可执行代码 / 可用数据”的桥，input 是“键盘 → 字符串”，两个连起来，才能把用户 typed 的东西变成程序能算的东西。**

### 2.5 eval 的三条红线（老师课上没展开，但后面一定要知道）

**1. eval 只算表达式，不执行语句。**

```python
eval('1+1')      # 可以，表达式，有返回值
eval('x = 1')    # 报错，赋值是语句，不是表达式；要执行语句用 exec，不是 eval
```

**2. 参数必须是字符串（或代码对象），直接传数字会报错；字符串里必须是合法的 Python 表达式，否则报错。**

```python
eval(11)         # 报错，11 不是字符串
eval('1+')       # 报错，表达式不完整
eval('a + b')    # 如果 a、b 没定义过，会报名字找不到的错
```

**3. 安全红线：永远不要把不信任来源的字符串交给 eval。**

eval 会真的执行代码，字符串里写什么，它就执行什么。比如一段从网上、从用户、从文件里来的、你没检查过的字符串，里面藏了一句删文件、跑系统命令的代码，eval 也会照跑。在正式项目、联网程序、别人能输入的地方，不能图方便用 eval。

安全替代品，记住一个就够了：**只想把字符串变成数字、列表、字典、元组这些“纯数据”时，用 `ast.literal_eval`，它只认字面量，不执行函数调用和系统命令：**

```python
import ast
ast.literal_eval('[64, 128]')        # [64, 128]，安全
ast.literal_eval("{'lr': 0.01}")     # {'lr': 0.01}，安全
# ast.literal_eval('__import__("os").system("...")')  # 会直接报错，不执行
```

练习和课上实验可以用 eval 理解原理；以后做机器学习项目、读配置文件，优先用 `ast.literal_eval`、`json.loads`、yaml 解析这些安全办法，而不是 eval。

### 2.6 一个不要学的习惯：别用 `str` 当变量名

课上那份 `09.eval.py` 里为了省事写了 `str = 1 + 1`，但 `str` 本来是 Python 内置的“转字符串”函数 `str()`，你一旦写了 `str = ...`，这个名字就被你自己的变量盖住了，后面再想用 `str(123)` 转字符串就会出问题。

自己写代码时，改成这样：

```python
result = eval('1+1')
print(result)  # 2
```

意思一样，习惯是对的。
